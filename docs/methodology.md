# 黑盒靶场方法

## 目的

靶场用于建立一个可审计的观察流程：每次使用同一份本地软件样本，先做完整性校验，再在授权的演练会话中记录可见反馈，最后区分观察事实、统计推断和未知事项。它不以发现模拟器隐藏实现为目标。

## 样本完整性

`simulator/artifact-manifest.json` 记录程序及运行时文件的相对路径、文件大小和 SHA-256；`full-artifact-manifest.json` 记录完整的 272 个文件。完整样本本身通过 Git LFS 保存。以 `simulator/Jammers-simulator-full-win64` 为根目录运行以下校验命令时：

```bash
python3 tools/inventory.py --root simulator/Jammers-simulator-full-win64 \
  --manifest simulator/artifact-manifest.json --verify
python3 tools/inventory.py --root simulator/Jammers-simulator-full-win64 \
  --manifest simulator/full-artifact-manifest.json --verify --include-all
```

脚本会检查：

1. 清单路径必须是相对路径，不能包含 `..`；
2. 文件必须存在且大小、SHA-256 完全匹配；
3. 普通清单忽略 `.DS_Store` 和 `JammersSimulatorData` 运行状态；完整清单由 `--include-all` 生成并校验这些文件；
4. 出现额外文件只作提示，不自动删除；
5. 不把本地绝对路径写回公开清单。

样本变化后应生成新清单，并在观察记录中写明版本标签；不要覆盖旧证据。

## 一次观察的最小字段

| 字段 | 说明 |
| :--- | :--- |
| `session_label` | 自定义标签，不使用账号或队伍号 |
| `sample_manifest_sha256` | 清单文件哈希 |
| `mode` | `practice` 或 `unknown`；无法确认就不连接 |
| `question` | 题号；未知写 `unknown` |
| `visible_input` | 界面允许输入的内容，不填隐藏真值 |
| `visible_output` | 界面/API 返回的公开结果 |
| `virtual_time_s` | 返回的虚拟时间；与电脑墙钟分开 |
| `error` | 可见错误及发生步骤 |
| `evidence_path` | 本机证据的相对标签，不能提交原始敏感日志 |
| `claim_level` | `observed`、`inferred` 或 `unknown` |

记录时保存原始证据在本机受控目录，再生成脱敏摘要。公开观察摘要不应含机器人编号、账号、手机号、Cookie、请求 UUID 和个人绝对路径；完整样本中的运行状态需由使用者自行确认其公开权限。

## 黑盒实验设计

如果要判断场景是否变化，只统计公开结束页和合法反馈：源总数、全向/定向计数、耗时、反馈序列长度和失败类型。每个策略使用新演练会话，不在同一会话切换策略；报告样本量、缺失值和可能的选择偏差。只能写“在样本中观察到”，不能写成随机种子、分布或内部实现已被证明。

## 安全边界

禁止读取隐藏源、内存对象、加密日志、受保护网络流量或内部数据库；禁止调试器注入、补丁、绕过会话模式、自动点击正式测试和任何会改变测试结果的操作。遇到正式测试界面、未完成旧会话、清单哈希不匹配或不确定的请求状态，停止并先人工核对。

## 证据等级

| 等级 | 含义 | 例子 |
| :--- | :--- | :--- |
| A | 可重复的公开观察，有原始脱敏证据 | 页面显示的版本号、合法 API 返回 |
| B | 多次 A 级观察的一致模式 | 7 局演练都完成，需报告样本量 |
| C | 解释性假设 | “可能从案例库抽取”，必须写作未证实 |
| U | 当前未知 | 随机种子、服务端生成逻辑 |

## 结果写作

每个结论都写明样本、方法和边界。例如：

> 在 7 局已授权演练中观察到源数量和类型组合变化（A/B 级证据）；现有公开反馈不足以区分固定案例抽样和运行时生成（U），因此客户端继续按未知场景设计。

不要把“程序成功启动”“页面显示结果”或“本地测试通过”写成官方成绩。靶场输出也不等于竞赛提交材料。
